About

I'm Edward Penna — IT support and systems administration, with a B.S. in Cybersecurity from SUNY Albany.

I run a self-hosted Linux server that keeps a fleet of always-on services alive: bots, data pipelines, scheduled jobs, remote administration. That's where most of what I know actually came from. Not from following tutorials, but from things breaking at inconvenient times and having to read logs until I understood why.

The labs on this site are built the same way. Each one is a system I stood up, attacked or broke on purpose, fixed, and then documented well enough that I could rebuild it from the notes. The code matters less than the operational habit: keep it running, know why when it isn't, manage secrets properly, and write it down so someone else can take it over.

Now / Learning

Studying for CompTIA Network+.

Alongside it I'm working through the gap between "I built this once" and "I could run this for someone else." Recent things that changed how I work:

  • An untested backup is not a backup. The restore drill in the backup lab is logged for a reason — the first one I ran didn't work.
  • Triage by risk, not by CVSS. A critical on an isolated box matters less than a medium on the thing everyone logs into.
  • Detection is written, not bought. Standing up a SIEM is the easy half; the value is in the rules you write after watching your own attacks go through.
  • Write it down while it hurts. Every runbook here exists because I'd already had to rediscover the same fix twice.

Colophon

How this site is built, since that's part of the portfolio too.

  • No framework, no bundler, no build step. Hand-written HTML, CSS and ES modules. What you see in view-source is what I wrote.
  • Project data is baked at build time. A script pulls my public repos through the GitHub CLI into a local JSON file — pinned to --visibility public so a private repo can never leak into it. No API calls at runtime, so nothing here is rate-limited or breaks when GitHub is slow.
  • Hand-written copy is protected from the sync. Everything GitHub owns lives in one gh object the script replaces wholesale; the blurbs are joined by repo node ID, so renaming a repo can't silently destroy them.
  • Deployed by git push to GitHub Pages. The dev server mounts the site at the same subpath Pages uses, so path bugs surface locally instead of in production.
  • Fonts are self-hosted — no third-party requests, so visiting this page tells nobody but GitHub.
